# ADR 0001: Keep V0.1 single-process and single-backend

- Status: accepted
- Date: 2026-08-10

## Context

Multi-worker scheduling is attractive, but it multiplies failure modes before the basic request lifecycle is trustworthy. ServeLab first needs stable semantics for admission, streaming, cancellation, timeout, observability, and measurement.

## Decision

V0.1 uses one gateway process, one real vLLM HTTP backend, and one deterministic mock backend for tests. Routing exists only as an interface placeholder. Distributed state, Kubernetes, Redis, SGLang, autoscaling, and prefill/decode disaggregation are deferred.

## Consequences

- The first release can test lifecycle invariants without distributed ambiguity.
- Benchmark results establish a usable baseline.
- Later routing work plugs into already-observable interfaces.
- V0.1 is deliberately not a high-availability platform.
